# DoraPocket-Next

在用户需要帮助时，掏出合适道具的陪伴式能力口袋。当前第一阶段以工具选型与复用为核心落地形态：帮助用户更快找到此刻最值得用的工具，解释为什么这样选，并把高价值帮助沉淀为下次可直接复用的资产。

## 产品定位

- DoraPocket 不是通用聊天机器人、角色表演 Demo、工具导航站、纯 RAG 工具百科或收藏夹升级版。
- DoraPocket 的长期方向是“陪伴式能力口袋”，当前聚焦“找工具 + 比较候选 + 做出裁决 + 给出下一步动作”。
- DoraPocket 的长期目标是成为一个会随着使用不断变准的帮助系统，而不只是一次性推荐工具。
- DoraPocket 卖的不是工具列表，而是在需要帮助时被接住，并得到此刻最合适的帮助。
- 市场页服务选型，不服务闲逛；口袋页服务复用，不服务堆收藏；角色与语音是增强层，不是主任务流中心。

## 当前状态

### 已有基础

- 已从 Vite SPA 迁移到 Next.js App Router。
- 已补齐基础 BFF 路由：
  - `POST /api/chat`
  - `POST /api/aliyun/tts`
  - `GET /api/aliyun/nls-token`
- 已接入 `ESLint`、`Prettier`、`Husky`、`lint-staged`、`TypeCheck`。
- 首页、市场、口袋、成长页已形成统一骨架。
- 市场、口袋、偏好学习、Agent 候选与推荐解释已经具备产品雏形。

### 当前主线

- 项目正从“聊天壳子”转向“陪伴式能力口袋”的第一阶段：工具裁决与复用 Agent。
- 当前最重要的建设方向是强化单一主入口、提升“掏口袋时刻”的结果权威、让推荐与执行形成闭环。
- 长期会引入用户系统、持久化记忆、市场信号与知识底座，让 DoraPocket 越用越懂用户、越用越会出手。
- 推荐必须可解释，偏好必须可校准，沉淀必须让用户感知“下次更省事”。

### 当前主要问题

- 主场景还不够聚焦，用户未必能在首次使用中立刻感知核心价值。
- 首页与右侧区域的主次关系仍需继续收敛，避免多中心并发。
- 提示系统仍有进一步静默化空间，避免重复播报和过程过度暴露。
- `pocket-page` 仍残留旧市场分支代码，跨页转场与空间连续感仍可继续优化。
- 参数模板定位、任务起手式、个人中心实化程度、内置工具触达路径仍需继续打磨。

### 近期进展（2026-04-22）

- 首页左侧工作区已收敛为三段式 Stepper：`说清处境 / 分析意图 / 推荐与行动`。
- Stepper 已进一步压缩为单行高的顶部进度条，只展示当前任务阶段，不重复展示额外说明。
- Step 3 已合并推荐、候选比较、动作与反馈，尽量在一屏内完成“先给结论，再给动作”。
- 首页与个人中心继续共用统一顶栏骨架，首页顶部栏已改为更贴近全宽工作台的布局。
- 右侧区域继续降级为角色展示与输入承载区，不再承担主裁决表达。
- 底部输入区已改为更轻的一行式结构：左侧单圆形图标切换文字/语音，中间完成输入，右侧保留发送。
- 内置道具入口已从输入栏移至右侧哆啦A梦展示区右下角固定 FAB，减少对主输入链路的干扰。
- 本轮改动明确保留右侧哆啦A梦 3D 主体，不以压缩角色空间换取功能堆叠。

## 产品原则

- 帮助优先于工具：用户要的是当前最需要的帮助，不一定只是一个工具。
- 裁决优先于推荐：先给结论，再给理由，再给动作。
- 复用优先于收藏：沉淀必须带来下一次直接收益。
- 推荐不是普通榜单，而是由用户偏好、情境判断、市场信号和结果反馈共同驱动的裁决。
- 反馈优先于点赞：复用、跳过、替换、不适合等真实结果，比单次喜欢更重要。
- 单一主线优先于多入口并列：用户必须清楚从哪里开始、看哪里结果、下一步点哪里。
- 陪伴不等于话多：关键时刻接住用户，用短、明确、有温度的方式给出下一步。
- 市场与 Agent 必须共享同一候选顺序和解释逻辑，避免解释层与执行层割裂。
- 用户偏好与市场信号必须参与排序，并以可理解的方式暴露给用户。

## 技术概览

- 框架：`Next.js App Router`
- 语言：`TypeScript`
- 样式：`Tailwind CSS`
- 质量控制：`ESLint`、`Prettier`、`Husky`、`lint-staged`
- 当前市场数据策略：优先本地闭环，基于 `localStorage` 跑通 MVP，再决定是否引入更重的后端持久化
