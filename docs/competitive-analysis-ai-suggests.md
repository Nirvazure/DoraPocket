# AI Suggests 竞品沉淀与产品建议

> 更新日期：2026-06-03  
> 分析对象：[AI Suggests — Find My Tool](https://aisuggests.ai/find)、[首页](https://aisuggests.ai/)、[Use Cases](https://aisuggests.ai/use-cases)  
> 对照项目：DoraPocket（`/analyse` 主舞台 + `/market` 道具库）  
> 关联文档：[competitive-analysis.md](./competitive-analysis.md)

## 一、竞品在做什么（一句话）

**AI Suggests = 大目录（400+ 工具）+ 轻决策入口（问卷得 Top 3）+ 结果型内容站（Use Cases 等工作流页）。**

对外主张：_Stop researching. Start deciding._ — 与 DoraPocket「不是目录，是裁决」同一战场，但实现偏 **问卷匹配 + 静态内容**，不是对话 Agent。

## 二、Find 页可拆解的产品手法

| 手法       | 竞品做法                                                    | 对 DoraPocket 的启示                                                             |
| ---------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 极低门槛   | 约 3～4 步：角色 → 目标/场景（含预算）→ 打分 → Top 3 + 理由 | 冷启动需要 **点选即可推进** 的路径，不能只有空白输入框                           |
| 进度可见   | 步骤 1/2/3/4 +「How it works」三格说明                      | 与现有 `decisionSteps`、场景区说明一致，可加强 **选完即进入分析** 的连贯感       |
| 输出可读   | 固定 Top 3 + reasoning                                      | 已有主推 + 备选卡片；可强化 **1 个先试 + 最多 2 个备选 + 为何不选其它**          |
| 信任包装   | 80K+ 用户、每周更新、无付费排名、453+ 工具打分              | 应展示 **体验条数、库内/外部推荐依据**，而非堆工具数量                           |
| SEO 借道   | 15 个 Use Case：难度、周期、3 工具栈、步骤、失败模式        | 用 Agent 逻辑做 **场景着陆页**，CTA 回 `/analyse`，不把 `/market` 做成第二目录站 |
| 多入口矩阵 | Alternatives / Industry / ROI / Before You Buy 等           | 不必复制 10 个子产品；学 **多 JTBD 入口、一个品牌** 即可                         |

## 三、与 DoraPocket 现状的对照

```
AISuggests /find     →  角色/场景问卷 → Top 3（浅、快、可 SEO）
DoraPocket /analyse  →  任务文本/语音 → Agent 多轮 → 先试一个 + 行动闭环
```

**已有能力（不必从零造）：**

- `where-to-start-section.tsx`：3 个场景卡片，点击后 **仅填入输入框**（`handleDraftTask`），用户仍需自己发送。
- `compact-decision-panel`：`PrimaryRecommendationCard` + `CandidateAlternativesCard`（主推 + 备选）。
- `step2-action-row` + `quick-replies.ts`：澄清轮 quick reply（目前主要覆盖「城市」等少量预设）。
- `context-input-card`：提示可补预算、登录、语言等，但 **多为文案提示，少可点选项**。
- 体验飞轮：`/market` 投票/评分/标签 — 竞品目录站普遍没有。

**明显缺口：**

1. **Step 1 缺少「选完就能开跑」**：场景卡 ≠ 结构化约束 + 一键开分析。
2. **请选择未贯穿澄清轮**：`missingInputs` 与 quick reply 覆盖太窄。
3. **对外信任叙事弱于竞品**：体验数据、更新节奏未产品化展示。

## 四、战略边界（不要学错）

| 建议学                              | 建议不学                           |
| ----------------------------------- | ---------------------------------- |
| 轻入口、点选降门槛                  | 400+ 工具全覆盖目录                |
| 结果区结构化、信任信号              | 纯问卷一次性匹配（放弃多轮 Agent） |
| 场景型 SEO 着陆页                   | Top 3 平等并列，削弱「先试哪一个」 |
| 失败模式 / 踩坑提示（对齐体验投票） | 变成 affiliate 导购站              |

定位锚点（保持）：

> **AI Suggests 根据角色给 Top 3；DoraPocket 根据你此刻的具体任务 + 真实体验，裁决一个先试选项并推动下一步。**

## 五、当前最应优先改的功能（单点）

### 推荐：**`/analyse` Step 1 —「结构化冷启动入口」**

**原因（按优先级）：**

1. **新用户最大摩擦在「第一句话」**：竞品用 3 次点选即可看到结果；你们场景卡只填草稿，决策仍卡在「会不会打字 / 怎么描述」。
2. **与护城河一致**：点选内容应转成 Agent 的 **结构化上下文**（角色、约束、任务草稿），而不是另做一套静态推荐引擎。
3. **投入产出比最高**：主要改 Step 1 UI + 提交 payload，不必动 LangGraph 主链路；后端可逐步把约束写入 `task_frame` / prompt。
4. **和你个人偏好一致**：「请选择」最适合放在 **冷启动与澄清**，而不是替代深度对话。

**不建议当前单点主攻：**

- 扩 `/market` 目录规模（和 toolhunter 类卷广度）。
- 重做推荐算法（在入口没收敛前，准确率提升难感知）。
- 先做 Newsletter / SEO 矩阵（没有稳定「第一次出手」体验，获客难留存）。

## 六、是否需要「请选择」？

### 结论：**需要，但要分层使用，不能全场问卷化。**

| 阶段                     | 是否用请选择 | 形式建议                                                                                                               |
| ------------------------ | ------------ | ---------------------------------------------------------------------------------------------------------------------- |
| **冷启动（Step 1）**     | **强烈建议** | 身份/场景（单选或多选其一）+ 约束 chips（免费、免注册、要引用、中文优先）+ 可选一句话；提供 **「按当前选择开始分析」** |
| **Agent 澄清（Step 2）** | **建议**     | 将 `missingInputs` 映射为 **可点 chips**（扩展现有 `quick-replies.ts`），保留输入框补一句                              |
| **已有足够上下文**       | **不必**     | `context-input-card` 保持「可补可不补」的轻提示                                                                        |
| **结果页（Step 3）**     | **选择性**   | 行动按钮（打开/口袋/记录体验）为主；可选用「换一个约束重判」类 chips                                                   |

**设计原则：**

1. **点选 = 结构化输入**，提交时拼进 user message 或 `task_frame`，不是纯 UI 装饰。
2. **2～3 屏内见到价值**：最多 1 屏点选 + 1 句任务（或选场景即带任务），避免 AISuggests 之外更长 wizard。
3. **始终保留「直接描述任务」**：给熟练用户短路，避免只剩问卷感。
4. **不要替代多轮 Agent**：点选解决「说不清」，Agent 解决「判不准」。

## 七、结构化冷启动 — 建议形态（供后续 PLAN）

**第一屏（可并入 `WhereToStartSection` 演进）：**

1. **我是谁（可选单选）**：创作者 / 办公效率 / 开发 / 市场 / 其他 — 不必照抄竞品 9 角色，先 5～6 个高频即可。
2. **这次在意（多选 chips）**：免费优先、免注册、要引用来源、最快上手、中文体验 — 与现有场景卡 chips 统一词表。
3. **任务（三选一）**：点预设场景 **或** 选「办公小工具」类 **或** 输入一句话。

**交互：**

- 主按钮：**开始分析**（带齐结构化上下文，一次 `runAgentTurn`）。
- 次入口：**跳过，直接描述** → 聚焦输入框（现状）。

**成功标准：**

- 新用户无需构思长 prompt 也能触发第一次推荐。
- 首屏停留 → 首次推荐转化率可观测（埋点：`starter_path=structured|freeform`）。
